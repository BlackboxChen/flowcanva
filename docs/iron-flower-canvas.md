# 打铁花序幕画布

画布：<http://127.0.0.1:16789/canvas/#/?canvas=cv_7306ce4b>

## 使用顺序

1. A 区复用人物、道具、场景资产，或单独重新生成。
2. K 区生成或修订八张关键帧；K03 预置最后确认的一手一棒握持修正版。
3. 先检查关键帧并完成修稿。
4. 双击对应 V 节点，检查自动绑定的上游关键帧和动作提示词，勾选确认再执行。参考图或提示词变化后需要重新确认。
5. 节点使用内网 ComfyUI `10.88.0.3:8179`，实际 API 图已写入各节点。图片由本地后端上传后替换到 ComfyUI 图中。
6. 主体七镜裁为 5/4/6/6/4/5/8 秒，再接七秒片名动画，混入音轨，输出四十五秒成片。画布没有剪辑渲染引擎，这一步使用 FFmpeg 或剪辑软件。

原稿保留原文；第3镜原文的举棒动作已由后续确认的低位握持方案替代，应以 K03/V03 和人工确认说明为准。

## 节点能力

- Qwen Image 2.1 资产和关键帧生成。
- MiniMax H3 Timeline 逐镜生成；高级节点提供七镜批量素材工作流。
- 视频等待窗口为三十分钟；保存任务编号，可查询上次任务而不重新提交。
- 所有二十三个生成工作流默认每次执行随机种子，生图与视频均适用。随机数在浏览器中生成，以 JSON 整数写入本次提交的采样器输入，兼容现有后端。查询上次任务不会生成新种子。
- 节点面板可切换“固定种子”或“工作流原值”；“上次提交种子”记录服务器接受任务时使用的值。原种子保存在 fixedSeed，JSON 的种子改为明确的 `{{random_seed}}` 占位符；提交前会替换为整数，选择工作流原值则使用保存的原种子。
- 随机模式另保存在节点 config 中。旧页面保存内容时遗漏新字段，新版页面仍可从 config 或随机占位符恢复模式，避免刷新回退。
- 已导入的历史素材和成片用于对照，新生成素材不会自动重剪成片。
- 后端在提交前将任务写入 SQLite，接收 ComfyUI 任务编号后由后台持续查询。关闭页面不会停止查询和保存，服务重启后会恢复待处理任务。下载结果清单先持久化，再下载文件；下载失败按退避策略重试，不重新提交生成请求。
- 结果接口仅返回已保存到 `/uploads/workflow/` 的媒体；使用 SHA-256 命名、临时文件与原子改名。原始远程地址只保留为来源记录。已完成任务直接读取本地记录，不依赖 ComfyUI 历史继续存在或服务在线。
- 新建和保存工作流、图片、视频及资产节点时，后端强制将媒体输出远程地址转换成本地副本；失败则拒绝写入并保留原内容。旧客户端或外部回填脚本不能直接保存远程媒体输出。输入参考图地址、文本内容与来源元数据不受此约束。
- 新前端要求后端能力 `persistent_jobs=true` 和 `durable_media=true`，旧后端未升级时拒绝提交新任务。后台完成后按节点绑定回填，使用比较后更新保护并发编辑；旧表单保存不能覆盖新任务归属或已完成输出。
- 数据库表 `workflow_jobs` 保存任务、下载清单、本地结果与重试状态，`workflow_media` 保存来源与本地文件的映射。历史节点中可识别的最后一次任务在启动时导入；上游已清除历史且从未保存过的任务不能凭空恢复，不会因此自动重生成。
- 创建画布本身不会请求生成接口，也不改模型共享存储或内网转发。
- 执行前检查后端变量接口版本；旧后端会提示重启，不提交未替换的工作流。

## 重建 / 更新

在项目根目录执行（读取用户指定的已有生产目录）：

```powershell
python scripts/iron_flower_canvas/create.py --source "D:\sk_show\out\2026-10-22_000028_iron_flower_prologue"
```

状态、创建前后快照位于 `.run/iron-canvas/`。脚本根据该状态更新已创建节点；重新运行会重置这些节点的配置和人工确认状态，因此开始新修稿后不要直接重跑。

已有画布只更新种子模式可运行 `python scripts/iron_flower_canvas/randomize.py`。此脚本先备份实时画布，再仅修改种子模式，保留当前修稿、输出、任务编号、节点位置和连线，不提交生成任务。

已有工作流输出的远程素材可用 `python scripts/iron_flower_canvas/localize.py` 保存到本地。脚本备份当前画布，下载并校验本地副本 SHA-256，替换输出和关联变量的精确地址，保留来源地址。写入前检查并发修改，遇到变化停止，不覆盖新编辑。

本轮编译的后端程序为 `backend/.run/flowcanva-iron.exe`。需要在 backend 工作目录启动，继续使用原有数据库、上传目录和环境配置。更新代码后仍须重新编译并重启后端。

后端持久化升级程序为 `backend/.run/flowcanva-durable.exe`；运行 `scripts/restart-backend.ps1` 重启并确认新能力，`scripts/start-local.ps1` 之后会优先选择新版。脚本只停止端口16789上路径属于本项目 backend 目录的进程，保留数据库和上传目录。升级前的一致性数据库备份位于 `.run/before-durable-*.db`。
