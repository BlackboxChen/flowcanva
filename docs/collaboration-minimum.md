# 内部协作最小版本

## 使用方式

所有浏览器需要连接同一个 FlowCanva 后端及数据库。不要在每位员工机器上各启动一份数据库。当前启动脚本仍使用原来的 127.0.0.1:16789 入口；其他电脑需要通过既有内网转发访问同一服务。这里没有增加账号、权限或对外监听。

刷新页面后，右上角打开“协作与并发调度”。选择需要运行的工作流节点，按服务地址设置并发上限，再执行所选节点。默认上限为 2，可设 1–8。上限控制本应用登记的未完成生成任务，不代表 GPU 推理并行度，也不统计其他工具直接提交的任务。旧的 legacy 历史导入记录继续查询，不占新调度器名额。

工作流之间的连线及变量 sourceNodeId 是依赖；文本说明节点不阻塞执行。未勾选的上游必须已经有可用结果。选中的上游必须在本批次成功完成，下游才会提交。循环依赖在建立批次时拒绝。一个分支失败，只阻止其下游。

需要关键帧确认的视频节点进入“等待人工审核”，不会由批次自动批准。请检查最新关键帧后，在视频节点面板确认并执行。批次会跟踪该次人工执行。停止后续调度只停止尚未提交的节点，不取消上游已接受的任务。修改排队节点的提示词会阻止其自动执行，需要重新建立批次；绑定参考图的 URL 刷新不属于人工改稿。

本轮批量调度覆盖 ComfyUI 工作流节点；普通图片、视频、智能体等其他供应商节点仍按原方式单独执行。

## 共同编辑

浏览器每 5 秒同步未选中、未保存中的节点；当前选中的节点保留本地编辑。内容、配置及位置尺寸保存携带客户端读取时的基准值，发生冲突时后端拒绝覆盖。出现红色“有未保存修改”后，在协作面板查看原因，选择对应节点，点击“导出当前节点草稿并加载最新版本”，再手动合并需要保留的修改。

提交生成前会等待当前节点保存完成；有保存冲突不会继续提交。仍建议按画布或节点分工。没有实现多人同时编辑同一段文字、实时光标或自动合并。

旧浏览器和外部导入脚本需要更新：PUT 节点内容带 expected_content，配置带 expected_config，移动尺寸带 expected_layout=[x,y,width,height]。缺少对应基准将返回 409，不应通过盲目重试覆盖。

## 资产

资产库可设置当前画布项目，并选择当前项目＋公共、公共、全部。项目名称相同的画布共享相同项目资产。新工作流结果入库继承画布项目；历史资产默认公共，可逐项修改项目。项目和标签是整理方式，不是访问权限。

删除资产只进入回收站，原文件保留，已有画布链接继续有效。回收站可恢复，资产卡可查看引用它的画布/节点。没有提供物理清空入口，因此磁盘使用量不会随软删除下降。

## 备份恢复

后端启动一分钟后创建备份，此后每运行 24 小时备份一次。协作面板可立即备份。删除节点和画布前也自动备份；备份失败则不执行删除。大量导入前建议手动备份。

备份目录为 backend/backups/<时间>/data.db、media.json，以及所有快照共用的 backend/backups/media/<SHA256>。数据库采用 SQLite 在线快照，包含已提交 WAL 数据；媒体按内容哈希保存。整个 backups 文件夹需要一起保管。当前备份在本机，不能抵御整块磁盘损坏；没有自动清理旧快照。

恢复命令（在项目目录执行，目标必须是全新目录）：

```powershell
python scripts/restore-collaboration-backup.py backend/backups/<时间> .run/restored-collaboration
```

恢复工具先校验媒体 SHA256，再恢复数据库和素材到新目录，检查 SQLite 完整性，并暂停快照内尚未提交的批次，避免旧生成任务被重跑。它不覆盖运行中的数据。确认恢复结果后，应在维护窗口停止后端、另行保留当前数据，再替换数据库及 uploads。不要把旧 data.db 与运行实例的 WAL 文件混用。
