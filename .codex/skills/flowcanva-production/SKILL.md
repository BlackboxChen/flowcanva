# FlowCanva 制作

目标是可继续编辑和追踪的真实画布。画布连线表达输入关系，单独连线不会自动执行或合成；用户启动批次后调度器会按依赖执行。

## 定位与读取

- 从用户提供的画布 URL 提取 canvas ID；未指定时列出 `/api/canvases`，依据项目名称定位，无法唯一确定才询问。
- 用户指定的画布 URL 和实例优先；未指定时先确定目标实例，不跨实例搜索、写入或假定同名画布一致。当前共享实例是 `http://10.88.0.3:16789`，Windows 本地测试实例是 `http://127.0.0.1:16789`；数据库及资产库相互独立。用户明确指向共享制作时使用共享实例；无法判断时先询问。读取项目 AGENTS.md。
- FlowCanva 实例地址与 ComfyUI 服务地址是不同配置。工作流服务从目标实例现有节点或用户配置获得；`127.0.0.1` 指执行该请求的机器，不能将 Windows 本地隧道直接当作服务器地址。共享实例的四卡 SGLang 路径尚未配置或验证，使用前单独检查，不将历史测试结果当成该实例的验证。
- 共享实例当前数据目录为 `/home/thao/flowcanva`：`data.db`、`uploads/` 与 `backups/`；凭据不写入 skill。地址与路径是当前部署信息，使用前核查实际配置。
- 使用 `scripts/canvas_snapshot.py --base URL --canvas ID --output PATH` 保存操作前快照。读取节点完整 content、config、edges，保留未知字段与用户布局。
- API 及执行细节见 [references/operations.md](references/operations.md)。

## 建图和修改

- 将项目组织为原稿、资产、关键帧、复核、视频、音轨、交付。镜头数量和长度服从剧本；已存在画布只增量修改。
- 将原稿按镜头编号保存为 sourceShots（id、raw），同时记录原文件 SHA256。画面、对白、旁白、音效保留原文；技术风格前后缀与原文分开，不能自行添加静音、无对白或后期配音等相反要求。制作方式变更须有用户依据，否则保留原意并报告能力缺口。
- 导入后运行 scripts/audit_source.py 对照原文件与重新读取的画布快照。检查实际 Timeline 分段引用的提示词，而非只检查节点里有没有原稿副本。原文覆盖检查不代表语音效果验证；另行记录语音路径、静音参考、模型能力证据和试听状态。
- 将配置与执行分别验收：“暂不生成视频”仍须建好真实可执行的视频节点，包括 API 工作流、服务器、提示词、时长、输入绑定与确认门槛。文字说明不计为视频节点。确有缺失时逐项报告，不能称建图完成。
- 多镜片段必须按原稿配置分段时间与镜头提示词，不把单镜工作流直接当作多镜工作流。检查服务端 object_info 中所用节点和参数；静态检查不能冒充生成实测。未经授权不能用提交任务来验证配置。
- 使用 MiniMax H3 有限分段采样时，先读 [references/minimax-frames.md](references/minimax-frames.md)，用脚本计算并校验每镜生成帧数；object_info 不包含全部运行时约束。原稿剪辑时长与模型生成时长分别保存，不能直接将秒数乘 FPS 后提交。
- 通过 API 建图，浏览器用于视觉检查。记录逻辑镜头编号与真实节点 ID；状态和快照按 base、canvas ID 分开保存。
- 参考图变量须绑定实际 sourceNodeId 并建立连线。检查变量类型和对应工作流占位符；不要猜测模型参数或复制不兼容工作流。
- 局部修稿只改指定镜头。修改前读取最新节点，合并目标字段；保留 outputs、lastPromptId、seedMode、lastSeed、用户改动及其他配置。上游改变时标记相关下游待更新，并清除受影响的 approvedFingerprint，不删除旧输出。
- 导入历史素材必须标注来源。输出是否存在、是否已确认、是否匹配当前输入是三个不同状态，不能互相代替。

## 生成与恢复

- “建图/修改画布”只执行对应编辑；用户要求生成时才提交所需任务。独立工作流可使用批次并发，遵守服务并发上限、失败隔离和依赖；复用仍有效的已完成结果。需要用户确认的关键帧必须暂停审核，不能自动代为批准。
- 尊重节点关键帧确认要求；不能替用户伪造确认。已有明确确认可沿用至相同输入版本。
- 随机模式在每次实际提交时产生有效种子，保存实际种子供复现；固定模式保持固定。遵循仓库 useWorkflowSeed.ts 的实现。
- 提交前记录输入快照，成功取得 prompt_id 后立即保存。超时状态不明时先查原任务，不盲目重发。轮询需有时限，结束时保存可继续查询的任务 ID。
- 外部修改后重新读取配置；提醒用户刷新已打开面板。以实际提交任务里的输入核对已确认版本，不能把服务端一次读回等同于浏览器已更新。
- 查询成功后核对媒体类型与 URL 可访问性，再把结果合并回原节点。失败记录错误，不标为完成。不将并发提交描述为 GPU 并行计算。
- 后期节点尚不存在时只提供真实剪辑清单；若用户要求实际合成，可调用本地 FFmpeg 并导入真实成片，不能用文字节点冒充渲染器。

## 交付检查

重新 GET 画布，核对节点、输入连线、修改字段、未改动素材及任务 ID。检查页面可打开；视觉验收尚未完成须明确说明。给出画布链接和实际变更，区分“已建图”“已提交”“生成完成”“已合成”。

逐片段核对：真实视频节点类型、可解析工作流、上游关键帧来源、变量占位符、镜头顺序与时长总和、输出媒体类型、确认门槛和未执行状态。任何一项缺失都列为未完成。
